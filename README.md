# 100 PEM electrolysis test scripts from simulated energy sources

Generated 2026-10-28 for the Test Script Generator project (see `HANDOFF.md` from the main project package).

Each script is a single-sheet test-engine matrix (.xlsx) for a **PEM water electrolysis** durability test driven by a simulated energy source, running **1,016 to 3,887 h** (average 2,458 h). Every script comes with a **set-point preview graph**, and each carries its **open questions** as `//` comment rows at the top of the sheet.

## How the scripts were made

All scripts were generated by code, not written one by one, so changing an assumption is a re-run.

1. **Energy profiles** (`profiles.py`): seeded synthetic hourly availability (fraction of rated power) for each source. PV uses day length and clear/partly/overcast day states; wind uses an AR(1) wind speed with a turbine power curve, including storm cut-out; there are also hybrids, batteries, CSP with storage, hydro, tidal, wave, OTEC, firm sources, grid markets and services, and compressed "accelerated" profiles.
2. **Scenarios** (`scenarios.py`): 34 sources, each with 2 to 4 variants forming a **comparison group**. Each group varies one factor: idle strategy, pressure, temperature, rated load, minimum load, cloud or gust transients, battery size, smoothing window, run hours, or outage handling.
3. **Script builder** (`gen.py`): profile → current set points via the idle strategy → merged matrix rows → loops → PostSteps.
4. **Checking**: every script was converted and checked by the **Test Script Generator itself** (`batch_xlsx.js` runs the tool's own writer and checker in a headless browser), so the sheets are identical to what the tool produces. Result: **100/100 with 0 errors and 0 warnings**. The library workbook was also re-read through the tool, again with no issues.
5. **Simulation** (`gen.py` `Sim`): every script was run as a timeline (rows, ramps, loops, PostSteps, $expressions) to confirm the 1000 to 4000 h duration, the rate limits (temperature 2 °C/min, H2 pressure 1 bar/min), and the interlocks (PSU only with water flowing and N2 purge off; N2 purge only with the PSU off and the H2 side depressurised; current 0 whenever the PSU is off). Result: **no violations**. The same timeline draws the graphs.

### Structure of every script
- **Pretest:** safe state → water circulation on → heat at 2 °C/min → Wait Til Settled → pressurise at 1 bar/min (if above 0 barg).
- **Matrix:**
  - Beginning-of-test diagnostics.
  - Then one or more **blocks** (a representative week, or a compressed cycle block), each repeated with `For CountA = 1 to n` in the matrix. The last row of each block calls **Diagnostics**, so the stack is characterised about weekly.
  - Seasonal sources use four sequential blocks (winter / spring / summer / autumn, with the starting season rotated across variants). Loops are never nested in the matrix.
  - End-of-test diagnostics.
- **PostSteps:**
  - `Diagnostics`: an end-of-life flag at 2.1 V after the 30 min reference hold at 1.0 A/cm², a temperature settle, then a polarisation curve in 0.25 A/cm² steps of 2 min (`For CountB`).
  - Fast-dynamics PostSteps use the `BASE_CD` variable: `Cloud flicker` (10 cloud passes, 40 % dips), `Wind gusts` (±25 %, 30 s period), `Wave oscillation` (±30 %, 10 s period), `FCR regulation` (±0.2 A/cm², 2 min period, 30 min).
  - `Crossover check`: raises the load if H2-in-O2 reaches 2 % while running at minimum or protective load.
- **Nesting:** at most 2 levels (matrix loop plus a loop inside a PostStep), as the engine requires.
- **Posttest:** unload → PSU off → depressurise → cool at 2 °C/min → N2 purge → safe state.

### Idle strategies (used when the source can't supply minimum load)
| Code | Strategy | What the script does |
|---|---|---|
| ML | minimum load | Holds j_min (8 % of rated by default) |
| SB | hot standby | PSU off, current 0, stays hot and pressurised |
| PC | protective current | Holds 0.02 A/cm² |
| PG | shutdown + N2 purge | For idle periods of 6 h or more: depressurise and cool to 40 °C, purge 15 min, idle under N2, then reheat and repressurise before restarting. Shorter idle periods use hot standby |

## Open questions
Each script lists 3 to 6 open questions (267 in total) in its sheet header and in the catalog. They come from:
- the **energy source**, e.g. "Does the predictable 12.4 h tidal cycle behave like PV cycling at twice the frequency?" or "Can the stack provide ±0.2 A/cm² regulation every minute without extra degradation?"
- the **idle strategy**, e.g. "Does a 0.02 A/cm² protective current prevent reverse-current degradation, and is its crossover acceptable?"
- **operating conditions**: high pressure, 80 °C, and the time resolution of transients
- **global assumptions** for the researcher to confirm (below)

## Assumptions to confirm before running on a real rig
1. **The tag file is a proposal.** `tags_pem_electrolysis.csv` was written for this exercise; your rig's tag names and limits must replace it. (Re-run with your CSV after updating the names used in `gen.py`.)
2. **Profiles are synthetic.** Measured site data (irradiance, wind speed, prices, grid signals) can replace the generators in `profiles.py`.
3. **Power maps to current linearly** (j = p × j_rated). A polarisation-curve mapping would be more accurate.
4. **Each representative week is replayed unchanged**, so real week-to-week variability is larger.
5. **Row timing is assumed to be ramp + duration** (rows were sized so each hour adds up to 3,600 s). PostStep timing is confirmed by the owner.
6. **Wait Til Settled is estimated at 360 s**, and the Conditional/Wait Til checks are assumed not to trigger, for the duration estimates and graphs.
7. **Graphs show set points, not measured values.**

## Regenerating
```
cd code
python3 gen.py                     # writes build/json, build/graphs, build/catalog.json (about 40 s)
node batch_xlsx.js <path to script_generator.html> tags_pem_electrolysis.csv   # writes build/xlsx + library + validation.json
python3 make_catalog.py            # catalog workbook + CSV
python3 make_gallery.py            # gallery page
```
Requirements: Python 3 with numpy, matplotlib and openpyxl; Node with Playwright (for `batch_xlsx.js`). To change the scenario mix, edit `PLAN` in `scenarios.py`; to change limits or timing, edit the constants at the top of `gen.py`. Seeds are fixed, so the same inputs give the same scripts.
